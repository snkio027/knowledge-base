## 01　定位、目标与关键决定

**长期目标：构建具有身体、感知、可靠行动、记忆和交互连续性的智能机器宠物。** 当前任务不是立即复刻四足机器人，也不是把大模型直接接到电机，而是建立从物理测量到智能行为的完整理解与实践能力。

本方案针对已有数学、C++23、Rust、Linux、并发与数据系统经验，但尚无硬件开发经验的学习者。已有的软件能力是起点，不是跳过电源、机械、采样与控制基础的理由。

### 主线与两条并行活动

**主项目：可测量的单轴运动系统 → 带反馈的桌面交互机器人 → 智能机器宠物原型。** 自主移动、机械臂操作、四足运动是后续分支，不构成必须逐个购买的升级阶梯。

基础实践线按 R0—R6 推进；前沿观察线从第一阶段开始，但先读论文、做仿真和数据实验，完成执行与安全基础后才让学习策略驱动真机。R7 用一个受控实验建立机器人学习闭环，不要求从零训练通用模型。

| 决策 | 本文建议 | 重新评估条件 |
| --- | --- | --- |
| 首个 MCU | 优先 NUCLEO-G474RE；ESP32-S3 是合理替代 | 已有板卡，或无线交互成为首要需求 |
| 首个运动项目 | 固定式、低功率、带 A/B 编码器的单电机实验台 | R0 电气与调试验收完成后接入 |
| 首个整合项目 | 桌面交互机器人，而非四足运动 | R1—R5 的必要能力通过验收 |
| 首轮计算平台 | 继续使用现有 Mac；按需补充 Linux 环境 | 真实负载证明需要独立运行或 GPU |
| 暂缓采购 | Jetson、高价工作站、四足整机、自组锂电池组 | 出现明确且可测量的需求与风险控制方案 |
| 暂缓建设 | 自研 PCB、机器人通用框架、云数据平台 | 现有模块已无法满足已验证的需求 |

### 完成后应能独立做什么

能读懂实际使用的电路与引脚资料；测量并解释单轴系统；实现可重复验证的闭环控制；把故障处理落实到真实执行器；组织坐标、时间和传感器数据；让一个小型机器人执行有边界、可取消的技能；比较规则控制与学习策略的实际效果。

> **状态边界：** 本文是建议学习基线，不是已购设备清单或已完成验收报告。硬件、预算、每周投入均未被假定为已经确认；所有实机指标仍需你在具体装置上测量。

## 02　能力地图：先补什么，后深入什么

基础不等于从头读完所有学科。每个主题都保留必要的概念、模型与边界，再由项目决定深入程度。能够运行厂商示例，只证明接入成功，不代表掌握了底层机制。

| 能力域 | 必须建立的基础 | 对应实践与深入方向 |
| --- | --- | --- |
| 电气与测量 | 电压、电流、功率、回路、逻辑电平、上拉、去耦、仪表使用 | R0；后续信号完整性、电流采样、PCB |
| 嵌入式执行 | 存储布局、启动、中断、定时器、ADC、DMA、调试、有限资源 | R0—R3；后续 RTOS、实时调度与驱动 |
| 机械与执行器 | 转矩、转速、惯性、摩擦、减速比、齿隙、固定与受力 | R1—R2；后续 CAD、机构、传动与热设计 |
| 控制与估计 | 状态、输入、输出、反馈、采样、饱和、稳定性、噪声 | R1—R4；后续状态空间、LQR、MPC、卡尔曼滤波 |
| 几何与感知 | 坐标系、刚体变换、相机模型、标定、时间对齐 | R4；后续视觉定位、融合与 SLAM |
| 机器人系统 | 接口、生命周期、资源归属、超时、回放、部署 | R3—R6；后续多传感器与分布式执行 |
| 智能与数据 | 任务定义、示范、动作表示、训练/测试划分、评测 | R7；后续 VLA、强化学习、世界模型 |
| 交互与体验 | 可预测动作、打断、主动性边界、隐私、可删除记忆 | R6；后续长期交互与行为设计 |

### 迁移现有经验，也要修正旧直觉

**可迁移：** C++ 的所有权与不变量可用于设备、缓冲区和状态机；Rust/数据系统经验可用于采集与回放；Linux 工程经验可用于诊断与部署；数学基础可用于控制、几何和概率模型。

**需要修正：** 吞吐高不代表控制及时；消息最终送达不代表动作仍然适用；进程重启不代表物理状态回到初始值；软件释放资源不代表机构已无危险；日志完整不代表系统已经安全。

### 数学按问题接入

先用微分方程和离散时间描述电机，再用旋转与齐次变换连接感知和关节；随后引入概率、噪声与估计。优化控制、动力学与强化学习在需要时展开，不用先完成全部高阶数学才能接触机器人学习。[S09](#S09)[S10](#S10)[S11](#S11)

> 首轮的重点是补齐“软件—物理世界”的连接，而不是继续扩展熟悉的基础设施，或同时学习多个 MCU、多个机器人中间件和多种固件语言。

## 03　系统模型：物理、控制与智能各司其职

本文采用分层模型，不把它当成必须实现的分布式架构。第一版可以只有一个 MCU 程序和一个电脑端进程；分层首先是责任与接口的划分。

| 层次 | 输入与输出 | 必须承担的责任 |
| --- | --- | --- |
| 身体与电源 | 电能、力、运动、热 | 固定、供电、保护、限位与可断能性 |
| 实时执行 | 测量值、设定值 → 驱动输出 | 周期控制、输出限制、本地故障响应 |
| 状态估计 | 原始观测 → 带时间与坐标的状态 | 标定、有效性、误差与过期判断 |
| 技能运行时 | 目标 → 有界动作序列 | 前置条件、资源互斥、取消、完成与失败 |
| 行为与策略 | 任务、观测、记忆 → 技能或动作建议 | 选择目标，处理不确定性，不绕过执行检查 |
| 数据与评测 | 观测、动作、结果 → 可追溯证据 | 回放、比较、复现与受控更新 |

### 三条流必须同时看见

**能量流：** 电源 → 驱动器 → 电机 → 机构。软件接口图不能代替供电与机械图。

**信息流：** 传感器 → 测量与估计 → 控制/行为 → 执行器，同时记录反馈。

**授权与停止流：** 人工启用、故障、取消、限位和断能路径。它应有明确的最终裁决者，而不是由多个进程各自猜测。

### 时间是接口的一部分

控制周期、传感器采样周期、相机帧率、策略推理时延和动作持续时间是不同量。必须分别定义截止时间、允许的数据年龄和超时行为；不能用平均 FPS 代表全部实时性。

本方案让 MCU 在上位机断联后仍能执行本地故障策略；高层通过有期限的目标与反馈交互。并非所有机器人都必须使用这套两层计算方式，但它适合本次低功率学习平台。

### 位置、速度、动作与结果不可混为一谈

“已发送目标角度”“驱动器已接收”“实际运动完成”“任务成功”是四种不同事实。技能完成必须依赖测量或明确可验证的完成条件，而不只是函数返回成功。

> **设计原则：智能层可以提出动作，执行层负责检查与落实；任何模型或云服务失效，都不应取消已定义的本地限制。** 这是一条学习项目的设计要求，不是安全认证声明。

## 04　学习协议、投入方式与验收规则

每个阶段按同一结构学习：**主题与前置知识 → 基础模型 → 机制 → 设计取舍 → 综合工程 → 反例与边界 → 复盘与验收。** 旧知识可以快速复习，但不从本卷删除。

### 每次完整练习的六个动作

| 动作 | 你要产出的内容 | AI 的合适角色 |
| --- | --- | --- |
| 闭卷解释 | 用自己的话解释一个可检验命题 | 追问跳步、术语和遗漏条件 |
| 设计预测 | 画模型；预测参数或负载变化后的结果 | 提供反例，不抢先给全部答案 |
| 实现 | 接线、代码、配置与测试 | 检查资料来源、接口与测试遗漏 |
| 测量 | 原始数据、曲线、仪表证据 | 帮助分析，不伪造实测结果 |
| 故障注入 | 在低风险条件下验证失败行为 | 检查故障矩阵和停止条件 |
| 压缩复盘 | 写明修正了什么、何时不成立 | 用迁移问题检验掌握程度 |

### 通过标准不是“看完”或“跑过一次”

阶段验收要求同时具备解释、可运行产物和证据。未执行测试标为 `NOT RUN`；失败标为 `FAIL`；只有条件、记录和结果都齐全才标为 `PASS`。板卡、固件或关键参数改变后，相关验收需要重跑。

每阶段只新增少量复杂度：先固定硬件与采样方式，再改变控制器；先把技能协议跑通，再接入模型。遇到问题先建立最小复现，避免一次同时更换电机、驱动、操作系统和模型。

### 基础与前沿的投入比例

建议早期把约 70% 的学习投入用于基础与实物实验，20% 用于仿真和系统整合，10% 用于前沿阅读。这是调度建议，不是课程规定。进入 R6—R7 后，可以适当增加数据、模型与评测的比重。

日历只安排学习时段，不代替验收。每轮规划保留排障与整理时间；被接线或驱动问题卡住时，缩小实验，不靠追加采购“推进进度”。

### 阅读材料的分工

教材用于建立模型；数据手册与原理图用于确认设备事实；官方文档用于接口与兼容性；论文用于理解假设、方法和实验；视频演示只用于观察行为，不能单独作为有效性或安全性的证据。

> 每次实验结束时，至少能回答：我原先怎样预测？测到了什么？差异来自模型、测量还是实现？下一次只改变哪个变量？

## 05　硬件选择：一个 MCU 生态，一套可调试工具

### 默认选择：NUCLEO-G474RE

建议以 ST 官方 NUCLEO-G474RE 起步。该开发板带 ST-LINK 调试/烧录能力；STM32G474RE 提供定时器、编码器接口、ADC、DMA 等适合单轴测量与控制的外设。这里的优势是调试与外设路径清楚，而不是“芯片越新越好”。[S01](#S01)[S02](#S02)

先使用厂商 SDK/HAL 建立基线，再选择 GPIO、定时器、编码器等关键路径深入寄存器。无需先重写全部驱动，也不要把代码生成工具的输出当成无需理解的黑盒。

### 合理替代：ESP32-S3

ESP32-S3 同样能完成本路线的早期实验。ESP-IDF 提供 MCPWM 和 JTAG 调试文档；无线交互更重要，或已经持有该板时，可以直接选择它，不必因本方案倾向 STM32 而换板。[S03](#S03)[S04](#S04)

接入时核实实际板卡的 USB 端口用途、引脚引出和调试路径。不要将“芯片支持”直接推断成“开发板无需其他电路就能使用”。第一阶段只学习一个生态。

| 工具 | 首轮用途 | 购买或使用要求 |
| --- | --- | --- |
| 数字万用表 | 测电压、电阻、通断 | 看懂插孔、量程与保险保护；先学使用 |
| 调试器 | 断点、单步、寄存器和故障定位 | 优先利用板载调试，不只靠串口日志 |
| 低压限流电源 | 为运动实验单独供电 | 在接电机前设置电压与电流限制 |
| 逻辑分析仪 | 看 GPIO、UART、编码器等数字时序 | 检查输入耐压、采样率与阈值 |
| 示波器 | 看电源波动、模拟信号与噪声 | 按实验需要借用/添置；先理解接地风险 |
| 固定与接线工具 | 保证接触与机械稳定 | 端子、支架、应力释放比外壳装饰更优先 |

### 不在第一轮比较的选项

不同时引入 FPGA、多个 RTOS、复杂电机控制芯片或自研无刷驱动板；不以 Raspberry Pi 替代底层测量与时序学习。Arduino 等封装并非禁用，关键是能解释其行为、测出代价，并在必要时穿透封装。

> 采购优先级：资料完整 → 可调试 → 电气兼容 → 可固定与测量 → 性能余量。模型名字、核心数或 AI 算力不应排在这些条件之前。

## 06　分批采购、参考组合与兼容性检查

### 采购按实验解锁，而不是一次买齐

| 批次 | 建议清单 | 解锁条件 |
| --- | --- | --- |
| A：R0 | 一块主控、数据线、万用表、面包板、LED、电阻、按键、电位器、连接线 | 开始电气与工具链学习 |
| B：R1—R3 | 单个带 A/B 编码器的低功率减速电机、H 桥、限流电源、固定支架、端子、断能开关 | R0 通过；供电与接线已审查 |
| C：R4—R6 | 按需选择相机、带反馈执行器、支架；音频设备后加 | 单轴控制、停止和恢复行为已有证据 |
| D：分支项目 | 底盘、SO-101、成品交互机器人或独立计算机 | 有任务定义、预算和替代方案比较 |

参考运动组合为 **Pololu 5113：100:1、LP 6V、带编码器减速电机**，配 **Pololu 2130：DRV8833 驱动模块**。前者标注 6V 下空载约 130 RPM、理论堵转电流 0.36A；后者标注每通道持续约 1.2A、峰值 2A，工作电压 2.7—10.8V。它是教学候选，不是唯一推荐或已经实测的搭配。[S06](#S06)[S07](#S07)

这些额定值不代表可长期堵转。实际散热、接线、负载、供电与模块实现仍需核实；峰值电流不能当作持续工作能力。电机线缆需按产品说明另行确认。[S06](#S06)[S07](#S07)

### 采购与上电前的七项核查

| 项目 | 必须确认的事实 |
| --- | --- |
| 电机与电源 | 额定电压、启动/堵转电流、允许负载、限流设定依据 |
| 驱动模块 | 实际板卡版本、持续能力、保护、散热、使能与刹车/滑行语义 |
| 编码器 | 安装在电机轴还是输出轴；CPR/PPR 的计数定义与解码倍率 |
| 信号电平 | 编码器输出与 GPIO/分析仪的输入范围相容；核查上拉电压 |
| 接线与连接器 | 精确引脚顺序、线材、接触、共地/隔离设计和回流路径 |
| 机械结构 | 轴、支架、紧固、线缆拉扯、夹点与转动空间 |
| 停止路径 | 软件停止之外，如何中断执行器能量；断能后机构会怎样运动 |

该参考电机的编码器输出被上拉至编码器 Vcc；Vcc 可在其规定范围内选取。不能因为电机用 6V，就让 MCU 输入直接接收 6V 编码器信号。[S06](#S06)

> 预算尚未指定，因此不编造精确总价。每批先列含运费、线缆、固定件、电源和仪表的总成本；有预算压力时缩小本体与自由度，不削减基本测量和保护。

## 07　开发环境、计算平台与版本策略

### 先使用现有 Mac，再由任务决定 Linux 与 GPU

Mac 继续承担编辑、交叉编译、数据分析与适合的仿真。ROS 2 集成优先使用受支持的 Linux 环境；虚拟机先验证 USB、网络发现和图形能力，不能将“容器启动成功”等同于硬件与仿真链路通过。

Reachy Mini 官方提供 MuJoCo 仿真，无需真实机器人；其文档包含 Apple Silicon/Intel Mac 的启动说明。它可作为早期交互观察窗口，但不替代单电机实测，也不保证全部音视频与物理行为和真机一致。[S17](#S17)[S18](#S18)

| 场景 | 建议基线 | 选择规则 |
| --- | --- | --- |
| 第一个 ROS 项目 | Ubuntu 24.04 + Jazzy + Harmonic | 延续成熟教程/驱动时优先；锁定组合 |
| 新 LTS 项目 | Ubuntu 26.04 + Lyrical + Jetty | 驱动与依赖均已验证时可直接选用 |
| 桌面交互仿真 | Mac + Reachy Mini/MuJoCo | 在隔离 Python 环境做小范围验证 |
| 重型视觉仿真/训练 | 符合要求的远程或本地计算资源 | 先验证模型、后端、显存和实际速度 |

Lyrical 于 2026-05-22 发布，官方声明支持至 2031 年；Gazebo 官方兼容表分别推荐 Jazzy/Harmonic 和 Lyrical/Jetty。本文不要求为了追新迁移一个已稳定的学习项目。[S12](#S12)[S13](#S13)[S14](#S14)

### 编程语言服务于责任，而不是扩大练习面

固件使用厂商 C 接口与 C++ 控制核心；分析、仿真和学习策略优先 Python；ROS 2 按模块需求选 C++/Python。暂不为了保持语言统一重写生态工具。

C++23 可作为你自有核心的设计目标，但应实测交叉工具链、标准库与运行时能力；`import std`、异常、线程、格式化和动态分配不能照搬桌面假设。ESP-IDF 的 C++ 文档也明确列有配置与限制。[S05](#S05)

### Raspberry Pi、Jetson 与工作站是分支

需要脱离电脑独立运行时，再评估 Linux 单板机；确定本地 GPU 推理需求后再评估 Jetson。Orin Nano Super 官方配置包含 8GB 内存、7—25W 功耗档，不能仅按 TOPS 判断模型是否可部署。[S21](#S21)

Isaac Sim 有专门的操作系统与 GPU 要求，当前官方要求并不把 macOS 列为原生支持平台；不要把 Apple Silicon Mac 或一块 Jetson 自动等同于完整仿真工作站。[S20](#S20)

## 08　R0：电气基础与可调试执行

**命题：程序中的输入与输出，怎样对应真实电压、采样值和时间？** 进入条件是能安排低压实验空间；此阶段不连接电机动力回路。

### 基础模型与机制

学习闭合回路、电压/电流/电阻、功率、共地、逻辑阈值、输入阻抗、上拉/下拉、RC 变化和去耦。结合 GPIO、按键、ADC、硬件定时器与串口理解数字抽象。MIT 6.002 可作为电路原理的系统补充，不要求先完整学完课程。[S08](#S08)

### 综合练习：可测量的输入—输出装置

用电位器提供模拟输入，以固定周期采样，通过 LED 亮度或数字输出表现结果；按键切换模式，串口只负责观测。保留一个可控版本，用于比较软件延时和硬件定时器的行为。

练习前先预测：LED 电阻减半会怎样？输入悬空时是否有稳定值？串口持续输出会不会影响周期？断点暂停期间外设是否继续运行？这些答案需要从实际配置与测量获得，不能统一猜测。

| 产出 | 验收条件 |
| --- | --- |
| 电路与引脚表 | 对每根线说明用途、电压与参考地；型号和板卡修订可追溯 |
| 工具链基线 | 能从干净工作目录构建、烧录；能断点、读寄存器并恢复运行 |
| 测量记录 | 至少比较数个输入点；说明理论值、实测值与误差来源 |
| 时间记录 | 用输出引脚或计时证据比较轻负载与日志负载下的周期 |
| 复盘 | 能解释为什么 GPIO 不能直接给电机供电、为什么浮空输入不可靠 |

### 反例与停止条件

在低压、无动力回路中测试按键抖动、错误配置与重启。不要用人为短路或错误供电作为“故障注入”。电压、插孔或引脚定义不清楚时停止上电，先回查实际资料。

### 进阶接口，不在本阶段堆叠

I²C、SPI、DMA 可以在需要传感器或高速采集时加入；此阶段先做到一个完整可解释的闭环实验流程，不以接入传感器数量作为掌握标准。

> **R0 完成门槛：** 不依赖复制接线图，能独立解释、测量并调试一个简单低压电路；所有接入运动硬件的前置核查已准备好。

## 09　R1：认识电机、编码器与测量误差

**命题：给被控对象一个输入，它实际怎样运动，测量又怎样影响判断？** 进入条件：R0 通过，电机已固定，供电、驱动与停止路径通过核查。

### 综合练习：单轴开环测量台

实现受限 PWM、方向控制、编码器计数、速度估算与记录。先以低能量条件验证方向和计数，再对数个输入点记录稳态速度与阶跃响应；任何负载变化都使用预先设计的低风险装置，不用手指夹住轴制造堵转。

补充转矩、转速、惯性、摩擦、齿隙与减速比。注意电机轴、减速器输出轴和传感器观测位置可能不同；“100:1”也不应代替产品给出的实际传动比。[S06](#S06)[S10](#S10)

### 两个必须自己推导的式子

```text
N_out = 每电机轴转的实际解码计数 × 实际减速比
ω_hat = 2π × Δcount / (N_out × Δt)      单位：rad/s
```

如果厂家 CPR 已包含双通道四边沿计数，不能再次乘 4；先解释定义，再在输出轴做标记验证一圈对应的计数。计数回绕、方向符号和读取一致性也必须覆盖。

**量化例子：** 假设输出轴每转 1200 个计数，固定 10ms 测速窗口的一计数量化约为 5 RPM；改成 1ms 后约为 50 RPM。这是由上式推导的教学例子，不是参考电机的实测性能。提高采样频率不必然改善低速速度估计。

| 产出 | 验收条件 |
| --- | --- |
| 编码器标定 | 说明 CPR、解码方式、轴位置、减速比；方向和回绕测试通过 |
| 输入—输出曲线 | 给出多个输入点与正反向对照，记录电压、测量窗口和负载 |
| 速度估计对照 | 比较固定窗口计数与边沿周期思路；解释噪声、延迟与低速局限 |
| 响应记录 | 保存启动、改变设定和停止的原始时间序列，不只保存截图 |
| 模型解释 | 区分“PWM 占空比”“实际端电压”“转速”与“转矩” |

> **R1 完成门槛：** 先能可信地测量，再谈控制；若比例、方向或时间基准尚不明确，不进入调参阶段。

<a id="sec10"></a>

## 10　R2：从模型到闭环控制

**命题：目标或负载变化时，怎样让实际运动按要求收敛，同时尊重执行器限制？** 进入条件：R1 的测量与标定可信，开环响应可复现。

### 建立最小模型，再逐步增加复杂度

从“输入影响速度，速度随时间变化”的一阶近似开始，用实测判断其适用范围；了解电机电气与机械动态，不把近似模型当成所有速度与负载下的真相。随后建立采样、误差、反馈、饱和与稳定性的概念。[S09](#S09)

先做 P，再比较 PI；只有误差与噪声分析证明需要时才增加 D。不要以“完整 PID”作为更高级的同义词。

```text
e_k = target_k - measured_k
u_raw = Kp × e_k + I_k
u_k = clamp(u_raw, lower_limit, upper_limit)
I_(k+1) = 根据明确的抗积分饱和策略更新
```

上式是算法结构，不是可直接烧录的完整控制器。必须补齐实际时间步长、启停时积分状态处理、非法输入、传感器有效性、输出方向及测试。

### 综合练习：有边界的速度伺服

完成受限设定值、加减速限制、速度控制、记录与停止；对同一套任务比较开环、P、PI。先在离线模型测试，再进行受控实机实验。控制周期从被控对象响应、测量质量与执行耗时确定，不直接照抄一个“标准频率”。

| 必测问题 | 证据与解释 |
| --- | --- |
| 稳态误差与响应 | 目标/实际/输出同轴展示；报告有效工作区间 |
| 超调与调节时间 | 预先定义容差带与观察窗口，不事后挑选最好的一次 |
| 饱和与恢复 | 验证设定受限、积分不无限累积，以及恢复过程 |
| 采样与噪声 | 比较窗口/滤波参数；指出平滑带来的时延成本 |
| 周期扰动 | 比较日志与计算负载下的执行耗时、迟到次数和控制效果 |

### 边界与反例

PID 不是消除错误接线、劣质测量和机构松动的万能工具。增加增益前，先检查单位、符号、传感器延迟与饱和。有限试验中的稳定响应不能证明整个工作域都稳定。

> **R2 完成门槛：** 能解释为什么控制器有效、在哪些条件下不再有效，并以重复实验比较方案，而不是只给出一组“手感不错”的参数。

## 11　R3：可靠固件与本地故障响应

**命题：通信、计算或传感器出错时，执行器还能否遵守明确的行为契约？** 安全设计从 R0 就存在；本阶段把它系统化并形成可重复测试。

### 状态、授权与恢复

建立 `DISARMED → ARMED → RUNNING` 以及 `FAULT` 状态。启用、开始运动、停止和故障复位是不同动作；上电、进程重启或重新连接后不自动恢复旧运动。复位故障不等于立即重新使能。

**首版责任划分：** 中断/控制路径只做有界工作；通信解析、日志与可视化不得阻塞控制。先用简单的定时器驱动结构，复杂度确有需要时再引入 RTOS。ESP-IDF 本身已有 FreeRTOS 基础，不为此强行改成另一个裸机平台。[S04](#S04)

### 通信契约的最低要求

协议应明确消息长度、版本、单位、合法范围、会话/序号、确认语义、有效期、错误处理与重连行为。CRC 只能帮助发现传输损坏，不能代替身份认证。第一版使用本地受控连接，不把裸串口接口直接暴露到公网。

“收到后有效 200ms”只能限制接收后的存活时间，不能识别此前已在发送端排队很久的命令。若要判断生成年龄，需要有误差界的时钟映射，或通过请求—响应、有限在途命令与会话更新等机制限制陈旧性；单靠序号不能证明新鲜。

| 故障试验 | 应验证的结果 |
| --- | --- |
| 上位机退出/停止发指令 | 本地在预定义条件下退出运行，记录检测与响应时刻 |
| 错误长度、NaN、越界值 | 拒绝输入，不破坏当前合法状态；错误可观测 |
| 重复、旧会话与延迟指令 | 不意外重放动作；重新连接必须重新授权 |
| 传感器冻结或异常 | 进入已定义的故障策略，不把失真反馈当作真实静止 |
| 日志队列满/串口拥塞 | 观测退化不拖垮控制；丢弃策略和计数明确 |
| MCU 重启 | 输出进入预定义状态；重启原因可查，旧命令不生效 |

对编码器断线等实验，优先通过仿真、软件注入或断电后调整接线，不在运转中随意拔线。

> **R3 完成门槛：** 不只是“能正常运行”，而是能展示断联、错误输入、重启和资源拥塞下的行为。看门狗是辅助机制，不是完整安全方案。

## 12　R4：坐标、感知、时间与状态估计

**命题：相机里看见的目标，怎样成为机器人能执行的方向或位置？** 进入条件：单轴测量可信；接入真实运动时必须具备 R3 的停止与恢复机制。

### 基础模型

学习点与坐标、旋转矩阵、齐次变换、变换顺序、关节零位、正运动学和工作空间；再引入相机内参/外参、畸变、检测误差和标定。Modern Robotics 的配置空间与刚体运动章节提供基础框架。[S10](#S10)

概率部分先补测量噪声、偏差、协方差与估计的意义。先用简单滤波和误差分析解决实际问题，再学习互补滤波、卡尔曼滤波或更复杂的融合；不要把滤波器名称当成准确性的保证。

### 综合练习：从画面目标到有限转向

先在静态相机和仿真头部上完成：识别一个简单标记或色块，计算相对画面中心的偏差，生成受限转向目标，记录观测与预测。之后才接入低速、限位的实体执行器。

必须区分相机坐标、机器人底座坐标、关节坐标，以及像素偏差和真实空间角度。单个距离传感器只给出其测量方向上的信息，不能凭一个距离值唯一确定目标在左侧还是右侧。

| 产出 | 验收条件 |
| --- | --- |
| 坐标与单位说明 | 明确轴方向、旋转约定、米/秒/弧度；能手工检查简单变换 |
| 标定记录 | 保存方法、数据、参数、残差与安装状态；重新安装后重新核查 |
| 时间契约 | 分别记录采集与接收时间及 clock_id；跨设备时间不能直接相减 |
| 跟踪实验 | 比较固定目标、移动目标和不同观测延迟下的误差 |
| 失效实验 | 遮挡、低置信度、画面停止更新时，不继续追逐旧观测 |

### 观测“新鲜”与“正确”是两个维度

刚收到的帧可能在队列中已经滞留；新拍摄的帧也可能因遮挡而错误。有效性检查至少应包含时间年龄、置信度/质量、坐标和单位一致性，以及与上一状态是否合理连续。

### 暂缓范围

首轮不要求同时实现 SLAM、深度学习检测、复杂多传感器融合和语音交互。先让一个简单观测稳定地约束一个可验证动作。

> **R4 完成门槛：** 能解释并量化观测到动作的变换、延迟与误差，目标消失或数据过期时行为可预测。

## 13　R5：ROS 2、仿真与真实硬件集成

**命题：同一套上层技能接口，怎样在仿真和真实硬件上保持一致的语义？** ROS 2 在这里是组织系统的工具，不是物理建模或安全性的替代品。

### 先学接口语义，再增加节点数量

围绕实际项目理解 Node、Topic、Service、Action、参数、生命周期、TF、URDF、日志与记录回放。持续状态流、一次请求、可取消的长任务应有不同接口，不把所有行为都塞进同一条字符串消息。

QoS 的可靠性、队列和时间设置需要与任务匹配；不要把“可靠投递”理解成“及时执行”。命令有效性和本地停止仍由应用与执行层明确实现。[S16](#S16)

### 综合练习：仿真/真机双后端

建立一个小型机器人模型、状态发布与受限技能接口；先接入仿真后端，再接入 R3 的硬件桥。让相同测试描述“转向目标、到位、取消、故障、恢复”，但分别记录仿真与真机结果。

需要标准控制器与硬件接口管理时再引入 `ros2_control`。它提供控制器生命周期和硬件接口管理；启动、激活、限制与故障策略必须显式配置并验证，不依赖默认值。[S15](#S15)

| 产出 | 验收条件 |
| --- | --- |
| 机器人描述 | 关节方向、限位、零位、尺寸与实际结构一致 |
| 后端契约 | 目标、状态、完成、取消、失败的含义在两个后端一致 |
| 生命周期 | 未启用时无运动；错误后不自动恢复；退出过程可观察 |
| 故障回放 | 对过期观测、通信中断、取消竞争等运行相同逻辑测试 |
| 集成记录 | 固定 ROS/Gazebo/依赖版本，记录构建、启动与验收步骤 |

### 避免双重控制与重复所有权

明确哪个层控制位置、哪个层控制速度、哪个层输出驱动命令。若 MCU 已做速度闭环，上位机通常发速度或轨迹设定；不要无意中让两个控制器争夺同一个变量或同时写同一执行器。

### 仿真能够证明什么

仿真适合验证接口、坐标、状态机和受控场景中的算法行为；它不能直接证明真实供电、摩擦、延迟、散热与安全性。记录模型与真机的差异，用实测校准，而不是调到“画面看起来像”就结束。

> **R5 完成门槛：** 用同一组任务语义控制两种后端，并能明确说出哪些结论可迁移、哪些仍需实机证据。

## 14　R6：桌面机器宠物原型

**命题：如何让机器人表现出连续、可理解、可打断的行为，而不把动作控制交给不受限的生成结果？** 本阶段整合已有能力，不追求一次实现完整人格或通用自主性。

### 第一版限定任务

在固定桌面空间内完成“待机—发现目标—转向关注—响应简单指令—被打断—回到待机”。可先使用按钮或文本指令，语音、对话和长期记忆逐项增加。机构只有必要的少数自由度，并限制速度、加速度和工作空间。

自制带反馈头部适合深入软硬件；Reachy Mini Lite 适合把精力转向交互。后者为电脑连接式平台，并有官方仿真入口；两者是不同路径，不是必须先后购买的两级产品。[S17](#S17)[S18](#S18)

### 技能合同优先于模型提示词

每个技能至少定义：输入与单位、前置条件、资源需求、最大持续时间、取消方式、成功条件、故障与恢复。示例技能为 `look_at`、`nod`、`idle`；这些名字不意味着可以绕过限位和新鲜度检查。

行为层先用状态机或行为树建立可解释基线。接入 LLM/VLM 后，只允许其提出任务或选择受限技能；最终动作必须经过结构化校验和执行仲裁。

| 场景 | 验收重点 |
| --- | --- |
| 正常交互 | 行为、实际状态和完成条件一致；不过度抖动或突变 |
| 人工打断 | 取消剩余动作；反馈是已请求还是已停止，语义明确 |
| 目标消失 | 不继续追逐旧位置；转为预定义低风险行为 |
| 模型超时/错误输出 | 拒绝或降级；不影响底层限制和停止能力 |
| 多任务冲突 | 对同一执行器只有一个当前控制者；旧任务不能夺回控制 |
| 重启与恢复 | 未授权前不恢复运动；会话与记忆状态有明确边界 |

### “宠物感”与隐私是独立设计问题

先研究注视、动作节奏、回应时机、主动性上限与可预测性，不用四足外形证明陪伴效果。将长期记忆限定为明确、可查看、可删除的数据；音视频默认最小化采集，不把原始记录自动上传或永久保存。

拟人表达是交互设计，不应被描述为已经证明机器人具有真实感受。首轮也不以人脸身份识别作为获得交互能力的前提。

> **R6 完成门槛：** 得到一个可以反复演示、可打断、故障可解释的小型交互机器人，而非一段只在理想条件下成功的视频。

## 15　R7：数据、模仿学习与任务评测

**命题：一个学习策略是否比现有基线更适合这个具体任务？** 本阶段可先在数据集与仿真中完成；接入真机前必须复用 R3—R6 的执行与保护机制。

### 从小任务与基线开始

选一个动作空间与成功条件明确的任务，先建立规则、轨迹回放或简单控制基线，再研究行为克隆和 ACT。LeRobot 官方把 ACT 作为入门策略之一，并提供训练与运行流程；不要把示例中的数据量或训练速度当作所有任务的保证。[S22](#S22)

随后可研究 SmolVLA：理解图像、机器人状态、语言指令如何形成条件，并生成动作片段。预训练能力不能自动消除你自己机器人的动作定义、标定与数据差异。[S23](#S23)

### 数据契约从第一条记录开始

至少保存 episode_id、任务描述、观测、实际状态、请求动作、接受/执行结果、采集/接收时间、clock_id、单位与坐标、人工干预、软件/硬件/标定版本。不能只存视频，也不能用目标角度冒充实测角度。

LeRobotDataset v3 提供多模态时序、状态/动作与视频数据组织方式；可在需要时转换或采用，不必在单电机阶段先建完整数据平台。[S24](#S24)

| 评测设计 | 要求 |
| --- | --- |
| 划分 | 按完整 episode、场景或采集批次划分；避免相邻帧跨训练/测试泄漏 |
| 任务成功 | 预先定义完成条件、时间上限与禁止动作，不事后改口径 |
| 运行质量 | 统计完成时间、人工接管、超时、限位/保护触发和失败类型 |
| 泛化范围 | 区分同场景复现、位置变化、物体变化与新任务，不混报成功率 |
| 重复性 | 固定模型、配置、随机种子和测试集；报告试验次数与不确定性 |
| 对照 | 与规则/回放基线比较；收益不足时保留简单方案 |

### 建议的第一次复现实验

先离线读取一个小数据集并可视化状态与动作；复现一个小型策略；在受控仿真中评测。需要真实操作数据时再选择 SO-101 等平台，官方文档可作为装配、标定与遥操作入口。[S19](#S19)

> **R7 完成门槛：** 能说明模型做了什么、依赖哪些数据、在哪些条件失败，并给出可复现对照；训练损失下降或一次成功不等于机器人能力已经提升。

## 16　前沿研究地图：跟问题，不只跟模型名

**核验日期：2026-10-26。** 下表是与本路线相关的代表性入口，不是全领域最新排名。论文、项目集成、产品发布和独立评测是不同证据，不互相替代。

| 方向 | 要理解的问题 | 最小实践与进入条件 |
| --- | --- | --- |
| VLA 与模仿学习 | 观测、语言和状态如何映射到动作；动作表示如何适配本体 | R7：ACT 基线后研究 SmolVLA，再比较更大模型 [S22](#S22)[S23](#S23) |
| 动作分块与异步执行 | 推理尚未完成时旧动作执行到哪；新动作怎样衔接 | R3 后可仿真延迟；R7 研究 Async/RTC [S25](#S25)[S26](#S26) |
| 人工干预与数据闭环 | 如何把失败与接管变成有效训练样本 | 记录请求、执行和干预；比较修正前后策略 [S27](#S27) |
| 世界模型与奖励模型 | 预测是否帮助决策；预测误差与奖励偏差如何影响行为 | 在既有基线之上做单变量对照 [S27](#S27) |
| 具身记忆与行为运行时 | 跨任务记忆如何影响选择，又怎样防止旧状态控制新动作 | 先做明确的小记忆与可取消技能，避免无边界自主行为 |
| 服务化机器人模型 | 托管训练/推理能减少什么工作，又增加什么依赖 | 只做受控验证；本地停止与离线退化不依赖云 [S28](#S28) |

### 已核验的近期变化

LeRobot 于 2026-07-07 发布的 v0.6.0 公告纳入世界模型、奖励模型、人工干预部署流程，以及包括 GR00T N1.7 在内的策略集成。这里引用的是该次发布的方向性信息，不宣称 v0.6.0 是核验日的最新补丁版本，也不将厂商性能陈述当作独立结论。[S27](#S27)

Physical Intelligence 于 2026-10-13 宣布 Pi API beta，描述了数据上传、托管微调与托管推理流程。beta 与一般可用、开放权重、本地部署不是同义词；采购与方案不能依赖尚未验证的可用性。[S28](#S28)

### 每篇前沿资料只回答六个问题

它解决哪个任务？观测与动作是什么？数据从哪里来？与什么基线比较？在哪些条件失败？在自己的平台上复现需要什么资源与授权？

每次只选择一个可复现实验。模型版本、代码、数据、许可证、硬件与测试条件一起固定；不得只凭演示视频决定更换本体或购买算力。

> 对你最值得持续深入的交叉方向是：**可靠技能执行、机器人数据与评测、时序与推理调度。** 这是基于已有能力与机器宠物目标的路线判断，不是市场收益承诺。

## 17　分支选择：不把所有机器人都做一遍

在共同基础通过后，按当前最重要的问题选择一条分支。更换本体不意味着丢弃数据、技能接口与评测方法，但动作模型、标定和保护需要重新验证。

| 分支 | 核心新增知识 | 第一项有边界的项目 |
| --- | --- | --- |
| 桌面交互（默认） | 动作表达、视觉关注、语音、任务打断、隐私与记忆 | 固定桌面空间内完成关注—回应—取消—待机 |
| 两轮移动 | 差速运动学、轮速控制、里程计、定位、规划与避障 | 先架空测轮速，再在封闭低速区域走预定路线 |
| 机械臂操作 | 正逆运动学、工作空间、碰撞、遥操作、示范与抓取 | 先仿真可达性，再低速操作轻小软质物体 |
| 四足运动 | 动力学、接触、平衡、状态估计、全身控制 | 先做受控仿真与已有策略分析，再考虑实机 |
| 深入硬件 | 电源、信号完整性、PCB、机构与热设计 | 先记录现成模块限制，再设计一块小接口板 |

### 自主移动不是“给头部装两个轮子”

移动后新增环境、跌落、碰撞与失联风险。需要补齐轮径/轮距标定、打滑、坐标与估计、障碍和悬崖风险控制。先证明基础运动与停止，再加入导航系统，不让导航演示掩盖底盘控制问题。[S10](#S10)

### 机械臂不是机器宠物的必修硬件

SO-101 等平台适合进入遥操作和机器人学习流程，但抓取能力与陪伴交互不是同一目标。只有操作任务成为研究重点时才购买；先读数据或做仿真完全合理。[S19](#S19)

### 四足是长期形态选项，不是入门凭证

四足运动会同时引入多关节动力学、接触、平衡和更高机械风险。通过 MIT Underactuated Robotics 等材料深入动力学、优化与控制后，可围绕一个明确研究目标开展；不要求先掌握所有理论才能阅读前沿论文。[S11](#S11)

### 进入更复杂硬件前的条件

已有低风险平台的控制与故障记录；能说明新增自由度/功率的必要性；有机构约束、人员隔离、停止与恢复方案；知道哪些旧假设因换本体而失效。任何一项不清楚，先在仿真或更小装置上验证。

> 路线的完整性来自能力覆盖与迁移，不来自开发板、传感器、机器人整机的收藏数量。

## 18　实验安全与故障响应边界

本章是低压、小功率学习实验的风险控制要求，不替代产品手册、合格电气指导或正式安全评估。它也不构成功能安全认证。遇到不熟悉的供电、测量或机构，先停止操作并核实。

### 电气与机械的基本约束

第一轮不接触市电、不自组锂电池、不用 GPIO 给执行器供电。电机动力回路使用匹配线材和可靠连接，不依赖松动的面包板接触。带电前检查电压、极性、短路、逻辑电平与限流；改变接线前断开相关电源。

万用表测电流需要正确的串联方式与插孔，不能将电流档直接跨接电源。[S30](#S30) 接地式示波器的地夹可能改变被测回路，未经确认不要夹到浮动节点。仪表实际使用遵循其说明书，不能只凭本文件操作。[S29](#S29)

电机必须固定，防止卷入、夹伤和线缆拉扯；不靠手捏轴测试负载，不故意长期堵转。参考电机厂家明确警告堵转可能损坏电机或齿轮箱。[S06](#S06)

### 停止不是一个万能动作

| 机制 | 作用 | 不能据此推断的结论 |
| --- | --- | --- |
| 软件取消 | 停止后续任务与动作排程 | 不代表驱动已停止，也不保证进程崩溃时有效 |
| 受控减速 | 在控制能力尚有效时限制减速过程 | 不适用于所有传感器/控制故障 |
| 驱动禁止或断能 | 移除某类主动驱动能力 | 机构可能继续滑行、下坠或释放储能 |
| 硬件限位/保护 | 限制特定危险情形 | 不覆盖全部方向、速度、温升与软件故障 |
| 看门狗 | 检测部分执行停滞并复位 | 不证明系统逻辑正确或复位后机构安全 |

首轮普通断能开关只称为实验断能装置，不宣称为符合标准的急停。每次换机构都重新判断：停止后是滑行、制动、保持还是下坠，哪种行为在该装置中风险更低。

### 安全的测试顺序

先纯软件/仿真注入，再无负载低能量测试，再在固定装置中增加有限负载。对错误数据、超时和队列拥塞优先软件注入；不要以电气过压、短路、撞击或人员进入危险区域验证软件。

> 出现异常发热、气味、烟雾、松动、意外运动或状态不明时，停止实验并按预定方式移除风险；不要继续加参数“观察一下”。

<a id="sec19"></a>

## 19　验证体系、指标与证据要求

建立四级验证：纯函数/状态机单元测试 → 软件仿真 → 硬件在环 → 受控任务评测。高层通过不替代低层验证；仿真 PASS 不能自动升级成实机 PASS。

### 指标必须带条件、口径和样本

| 类别 | 建议记录 | 如何避免误读 |
| --- | --- | --- |
| 控制 | 稳态误差、超调、调节时间、饱和时间 | 写明设定值、负载、容差带、单位与采样窗口 |
| 时间 | 周期、执行耗时、迟到次数、数据年龄、取消延迟 | 同时报分布、观测最大值与样本数，不只平均值 |
| 可靠性 | 指令拒绝、断联响应、故障恢复、丢日志计数 | 报告注入条件，区分检测与实际停止 |
| 感知 | 标定残差、跟踪误差、丢失/误检、帧年龄 | 区分观测错误和控制误差 |
| 学习策略 | 成功次数/总次数、接管、完成时长、失败类型 | 固定测试集；避免只展示成功案例 |
| 资源 | CPU、内存、队列、温升、功耗（能测时） | 同时记录软件版本、运行时长与环境条件 |

这里不给所有装置统一规定“误差小于 1%”“延迟小于 10ms”。阈值应在验收前，根据机构、测量分辨率与任务需求确定；不得测试后为通过而降低要求。

**观测最大耗时不是最坏情况执行时间证明。** 在有限条件下没有迟到，也不能据此宣称具备硬实时保证；需要说明负载覆盖、测量方式与未覆盖边界。

### 最低故障矩阵

覆盖非法数值、无效单位/模式、重复与旧会话、指令过期、观测冻结、通信断开、日志拥塞、人工取消、程序重启与电源恢复。对每项写明触发方式、检测机制、预期输出、恢复条件和证据位置。

### 每份证据包至少包含

实验命题与预测；硬件/接线/标定版本；代码提交与构建参数；原始数据及生成图表的脚本；测试条件与样本数；结果、异常和限制。日志中的“stop requested”不能冒充执行器停止的测量证据。

当测量工具或时钟不同，先说明同步方法和误差；不能把不同时间基准上的数值直接相减得到看似精确的延迟。

> 验收结论应写成“在这些条件下，这些测试通过，仍有这些未覆盖项”，而不是笼统的“系统安全稳定”。

## 20　代码组织与学习资产沉淀

保持一个小而清晰的项目，不在开始时建设完整机器人平台。目录按责任划分；只有出现真实复用或独立发布需求时才拆仓库。

```text
robotics-lab/
  README.md                # 当前目标、启动与已知限制
  firmware/                # MCU 工程与厂商适配
  control/                 # 可在主机测试的控制/状态机核心
  host/                    # 通信、可视化、数据采集
  simulation/              # 模型、场景与仿真配置
  ros_ws/src/              # 需要 ROS 2 时再加入
  tests/                   # 单元、故障注入与集成测试
  hardware/                # BOM、接线、引脚与标定说明
  experiments/             # 实验定义、配置、分析脚本
  docs/                    # 理解笔记、决策与验收记录
  manifests/               # 外部数据/模型的清单与校验值
```

### C++ 核心与设备边界

把速度估计、PI、限幅、状态转移等核心与厂商 HAL 隔离；显式传入时间与观测，便于主机测试。对角度、速度、时间和模式使用清楚的类型/命名，避免裸数值与隐式单位混用。

关键控制路径采用有界工作量与明确资源策略；是否使用异常、动态分配和线程分别做出决定并测量。厂商生成代码与手写业务代码分界清晰，升级时可比较，不为“纯现代 C++”重写整个硬件生态。

### 三种文档不能混成一份

**理解笔记**记录模型、反例与重新推导；**实验记录**保存具体条件、原始证据和结论；**决策记录**说明方案、替代项、取舍与重新评估条件。教材摘录和 AI 回答可以是输入，但不是掌握证明。

### 数据与版本

Git 保存代码、配置、文档与小型测试样本；大视频、模型和长日志放在合适的外部存储，用 manifest 记录路径、大小、摘要、许可和版本。早期本地文件即可，不为潜在规模提前引入 Kafka、Kubernetes 或湖仓平台。

每个实验使用唯一 ID，绑定代码提交、固件、硬件、标定和参数。采集后的原始数据尽量不原位覆盖；修正通过新版本与派生记录表达，保证能够重现旧结论。

> 本文的 Markdown 版本适合纳入知识库长期维护；Word 是阅读与批注版本。后续修改应选定一个事实来源，再生成其他出版格式，避免两份正文长期分叉。

## 21　推进方式与前十次学习单元

不以“12 周学会机器人”作为承诺。默认一轮只维护一个主要实物项目与一个小型仿真/前沿实验；按可投入时间安排学习单元，以阶段验收决定是否继续。

### 阶段依赖

**R0 → R1 → R2 → R3** 建立物理与执行基础。R4 的几何、静态感知和仿真可提前学习，但真机运动必须满足 R3。R5 在接口模型清楚后引入；R6 整合桌面宠物；R7 可先离线学习，真机部署仍受前述门槛约束。

| 单元 | 主要任务 | 当次应留下的产物 |
| --- | --- | --- |
| 1 | 明确第一个单轴实验，阅读板卡资料 | 目标、暂缓项、风险表、BOM 草案 |
| 2 | 学会万用表与简单电阻/LED 电路 | 计算、测量与误差解释；尚不接电机 |
| 3 | 构建、烧录、断点与重启 | 可复现工具链记录与第一次调试证据 |
| 4 | 按键输入、浮空与抖动 | 输入状态模型与异常实验 |
| 5 | 电位器与 ADC | 多点测量表、采样与误差解释 |
| 6 | 硬件定时器和串口观测 | 日志负载前后的周期记录 |
| 7 | 完成 R0 复盘与运动接入评审 | R0 验收、精确引脚表与停止说明 |
| 8 | 低能量驱动与编码器方向验证 | 转动方向、计数与电平核查 |
| 9 | 输出轴标定与速度估计 | 计数换算、回绕测试、量化分析 |
| 10 | 开环输入—输出与阶跃记录 | R1 首批曲线、模型假设与下一轮计划 |

这些是学习单元，不是十天完成计划；任何单元未通过都可拆分。并行仿真只占少量时间，不影响实物基础的验收。

### 每轮复盘只作三个决定

哪些命题已经有证据，可以冻结为当前基线？哪个缺口最影响下一步，需要定点补课？下一轮只新增什么复杂度？

如连续多次没有可解释的实测结果，优先减小项目：从两个电机退回一个、从视觉退回已知设定值、从多进程退回单一上位机。不要把“更大框架可能解决问题”当成默认答案。

> 第一项交付应是 R0 的可调试电气实验，随后是 R1 的测量台；不是一张采购大单，也不是一套尚未承载真实硬件的复杂架构。

### 采购决策模板

写明对应阶段与待解决问题、精确料号/版本、官方资料、现有替代品、接口与电平、电源/电流、安装与线缆、工具需求、总成本、风险和退路。最终结论只能是“购买”“复用”“借用”或“暂缓”，并附理由。

采购不能由一个孤立参数决定。例如驱动器电流裕量需要结合实际板卡与热条件；摄像头需要考虑驱动、时间戳和安装；计算平台需要考虑模型内存与端到端延迟。

### 前沿复现卡模板

写明任务与基线、论文/代码/模型版本、观测与动作定义、训练数据与划分、算力与依赖、许可证、成功标准、失败分类、复现差异，以及是否改变当前学习路线。

复现不成功同样可以形成有效资产：保留环境、错误、最小复现与已排除因素；不要将“没跑通”包装成“该方法无效”。

> 三类模板都是轻量记录，不要求每次写长报告。关键是能追溯结论，并让下一次实验少重复一次无效猜测。

修正文案或补引用可升补丁版本；改变实验与验收可升次版本；改变主线、硬件或关键架构应记录决策并升主版本。修改后同步 Markdown、Word 与目录；历史验收仍绑定当时的版本，不自动继承。
