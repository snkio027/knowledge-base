# Knowledge Base 架构实施与验收计划

本计划将[架构设计](architecture.md)收敛成少量可独立使用的能力增量。当前交付仅包含设计文档与本地目录更名；以下资产工具、备份和检索批次均未启动。每批内连续完成实现、反例测试、自查和修复，最后集中审核，不把每个内部步骤变成单独审批。

## 1 先确认部署条件

实施前由维护者明确外部归档根、缓存根、备份目标、凭证取得方式及恢复位置。备份频率、可接受数据损失窗口和恢复时间目标尚未确定，不在本设计中填入未经承诺的数值。已有可用备份层可以保留，但要通过一次本项目范围的恢复演练。

首期只支持本机 macOS，目录工具采用独立 uv 环境。进入实现时固定 Python、依赖、Schema 和证据适配协议版本；不能因引擎已经安装 pypdf 就直接复用它的环境。公共目录与受控原件的边界也需在首批样本选择时确认。

## 2 能力批次

### 第一批 文件盘点与恢复

先显式列出内容 checkout、历史忽略资产和用户指定外部材料的扫描与备份范围。在原位置计算文件清单和摘要，报告重复字节、读取失败及排除项，不自动移动、去重或删除。

选择少量代表性原件和既有发布包，完成备份及空目录恢复。验收要求恢复集合与声明范围一致、摘要匹配，并能打开所选原文件。此时不要求完整资产分类，也不声称历史构建已经可复现。

### 第二批 资产登记与证据归档

选择 20–30 个代表性资产，覆盖当前 Markdown、历史原稿、独立文档、多文件手册、实验、发布 PDF 和来源不完整材料。实现最小资产卡、Schema 与项目语义检查；复用已有出版清单，走通一个真实候选或发布包的导入与恢复。

接收工具必须能明确区分资产、修订、候选、授权与实际发布事实，并保留未知或冲突。首次冻结包 ID 序列化规则时提供固定测试向量。先用临时目录验证失败与取消，再触及真实归档目标；不得拿历史制品做破坏性实验。

### 第三批 查找与回到来源

增加 Markdown／代码字面量搜索、PDF 逐页文本缓存及可重建目录。使用 30 条来自实际阅读和工程回查的查询，而不是为工具演示临时造词。查询集至少包含中文单字与短词、带符号的标识符、旧 ID、别名、固定版本、跨文件关系和历史 PDF。

每条查询记录期望定位、实际定位、物理页号或文件位置、漏检原因与耗时；不把“命中一些文字”当作找到正确修订。至少包含一个空文本 PDF 和一个提取失败样本，用于确认覆盖缺口可见。删除测试缓存后应能重新生成相同来源绑定，不依赖缓存才能找到原件。

### 后续批次 由真实不足触发

只有当查询延迟、过滤／排序、扫描件或桌面浏览出现可复现的问题，才评估 SQLite、OCR、复杂提取或图形入口。每个新增组件说明解决的具体失败案例、权威来源是否改变、迁出或重建路径及维护成本。没有观察到需求时停在简单工具组合。

## 3 必须覆盖的反例

| 场景 | 期望行为 |
| --- | --- |
| 文件改名或根目录更名 | 资产 ID 不变，定位更新；历史证据中的原路径不改写 |
| 正文只改一个字节 | 当前修订摘要改变，旧审核不自动覆盖 |
| 原件与维护稿字节相同 | 可报告重复字节，但不能合并身份或删除 |
| 文件名版本与正文不一致 | 读取已声明的正文元数据，显示差异，不自动修复 |
| 附件只有引用、未实际收到 | 显示缺失，不算入已保存来源 |
| 有输入清单但缺少实际文件 | 不报告来源完整；受限归档明确缺口 |
| 未知证据协议或状态矛盾 | 保留原记录，停止自动解释，不推断已发布 |
| `../`、绝对路径、符号链接逃逸或名称碰撞 | 在越界读写发生前拒绝 |
| 读取过程中源文件改变 | 标记不稳定，不将盘点冒充冻结快照 |
| 同包重复导入或同路径不同内容 | 完整核对后幂等返回，或明确冲突；不覆盖 |
| 复制、同步、提交前故障或取消 | 不留下可接受为成功的最终包 |
| 提交后登记／缓存失败 | 保留包与可对账状态，不制造矛盾终态 |
| PDF 提取为空、超限或失败 | 保留具体覆盖缺口，不当作无内容或全量搜索成功 |
| 删除缓存或原件更新 | 可重建；过期缓存不冒充当前内容 |
| 从备份恢复出额外或缺失文件 | 完整集合核对失败，不只检查已存在项摘要 |

这些是未来实现的验收要求，不是本轮执行结果。文件隔离、同步失败等测试必须在一次性目录或测试仓库中进行；不允许以修改受保护制品后再报错的方式通过安全验收。

## 4 验证与状态报告

实施报告分别列出文档／Schema 检查、身份与路径反例、归档完整性、恢复演练和搜索覆盖，不汇总成含义不明的“全部验证通过”。每类记录实际命令、工具版本、输入范围、结果、失败、跳过项及未验证边界。

资产能力的接受不重跑也不升级正文技术证据；旧 C++、性能或并发记录继续保持历史身份。归档和备份成功不授权公开分发，读取到 release manifest 也不等于独立确认远端当前状态。

完成条件是读者能找到材料并回到正确来源，维护者能说明接受的是哪些字节，恢复者能在空目录还原声明范围。若需要改变正文语义、覆盖冻结制品、上传受控资料或扩大权限，应停止该项并另行确认；普通实现缺陷在批内解决。

## 5 本地目录更名与接入

本地名称统一为 `knowledge-base`，英文拼写为 **knowledge**，不是 `knowage`。本次目录调整为：

```text
<项目父目录>/kb
→ <项目父目录>/knowledge-base
```

这是同一 Git checkout 的整体移动，不是重新 clone、复制正文或重建资产。远端已为 `snkio027/knowledge-base`，本次不再次更名 GitHub 仓库，不移动 release tag，也不遗留旧路径下的兼容出版入口。

更名前确认目标不存在、工作区没有冲突改动，并保存受保护文件集合与摘要；更名后检查 Git 身份、origin、跟踪及未跟踪文件、历史资产字节。除新增设计文档和入口说明外，已有正文、实验、PDF、历史记录及四份未跟踪 Zig 材料保持不变。

历史日志、manifest 和固定 profile 中的旧绝对路径继续表示当时执行环境，不能批量替换。新的出版工作区通过独立产品入口重新指定当前内容 checkout；旧工作区的配置和输入身份不冒充新配置。编辑器或桌面应用仍记住旧路径时，重新打开新目录；不通过修改应用私有数据库修复路径。

本地检查不证明所有第三方软件的路径引用已更新，也不构成一次备份恢复演练。实际更名、检查、提交及推送结果在本批交付记录中报告。
